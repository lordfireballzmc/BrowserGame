## User-reported defect
In the actual user-provided active wave-1 screenshot (not committed to public source), enemy and Warden source rig facings were wrong relative to their real travel and target directions. The 53°-above-horizon default orthographic camera read as a near-overhead map and did not adequately show the 3D figure silhouettes. The user expressly rejected that presentation.

## Actual implementation
- `src/engine/render/RiggedCharacterLayer.ts`: every loaded KayKit Warden/Scrapper/Runner glTF rig now has a shared **π-radian Y-axis adapter outside its animated source skeleton**, aligning artist source +Z-forward with source game yaw local −Z-forward. No edits to source GLB binaries, physics matrices, target angles, HP, travel trajectories or skeleton clips. The existing fallback legacy meshes remain.
- `src/engine/Camera.ts`: `OrthoCamera` supports a gameplay-only 35.264° elevation, 45° azimuth, 28m visible world height, 0.22s exponential follow. The map/general overview retains the prior 53°/31m/0.17s configuration and unchanged map ray-casting behavior. Pure bounded `combatCameraLead` shifts no more than 3.25m toward an actually living nearby threat with velocity lead.
- `tests/terrain-preview.html`: the real `?view=movement` uses the new camera profile; no separate WebGL canvas or staged mockup. `scripts/probe_unified_chrome.mjs` requires actual `cameraProfile=combat`, `cameraElevation=35.264`, and `rigFacingCorrection=π` in source-exact real-browser gameplay.
- `tests/camera.test.ts` and `tests/rigged-character-art.test.ts`: camera/viewport/picking/3D appearance and visual-only heading adapter tests.

## Source, provenance, production strategy
- **Artist:** Kay Lousberg (KayKit), published [Adventurers 1.0](https://github.com/KayKit-Game-Assets/KayKit-Character-Pack-Adventures-1.0), with its author's own `LICENSE.txt` explicitly **CC0 1.0 Universal**. All three characters are from the **free core pack**, not the separately paid EXTRA or SOURCE content.
- Pin EXACT upstream commit `672074b73ba276876a19e8816ecdc5241817ab47`; source GLB blob pins: `Knight` 717b56ca2b5ff5392679774725201ba03a3eefab, `Barbarian` 66d312ab6dc02b35fb648e7585bfdddb4e02eeef and `Rogue_Hooded` 5d2b1403240d5f9ffff12e02c017572038eca2a8. `scripts/ingest_kaykit_characters.py` verifies Git-object source hash before repacking and refuses unsupported source GLB structures.
- `public/assets/characters/{warden,scrapper,runner}-kaykit.glb`: **588,336 / 542,424 / 526,992 bytes**, **1,657,752 bytes total** vs ~10.87MB of original content. Precisely recomputed SHA256 in `.sha256` and `public/assets/characters/manifest.json`. GLB retains 3D artist mesh vertices, one true skin/skeleton, the original gradient atlas texture and exactly **five real animations per role:** `Idle`, `Walk`, `Run`, `Attack`, `Death`. Extra 70 source animations and orphaned accessors/bufferViews are dropped to reduce game transfer and decoding cost without altering authored geometry or copied copyrighted game IP.
- **No runtime CDN, paid source, borrowed Kingshot/Kingdom Rush character assets or generated fake 2D billboards.** Assets are licensed third-party prototypes, not original final IP designs. Their use for baseline does not mean Bastionfall's distinct armor/hero/corps identity is finished.

## Runtime technical integration
- `src/engine/render/RiggedCharacterLayer.ts` owns original source prototypes and genuine `THREE.SkinnedMesh` `SkeletonUtils.clone` actor instances, one `AnimationMixer` per independently moving character, curated bone clips, ground-normalized real height and direct GPU-shadow shared-scene rendering.
- `UnifiedThreeRenderer` suppresses primitive Warden/Scrapper/Runner draw entries **only after all three separate rig/texture/animation sources load and validate**. The original instanced models remain functional as **fallback** if character decoding fails. Background assets do not block normal Warden input; strict browser screenshot probes await GLBs. Full map/cinematic static scenes load before their first frame. No second canvas or scene.
- Actor transforms, incl. yaw, ground height and motion progress, come from the unchanged immutable Warden and road enemy snapshots. The animator selects idle, authentic rigged run/walk, real hero attack pose at the most recent 60Hz bolt shot, and a one-shot death pose. It cannot move actual characters, change HP or alter deterministic projectile collision. Rendered animations do not advance simulation and pause/visibility freezes world-derived locomotion time.
- Prototyped a strong **blue Warden / crimson Scrapper / deeper red Runner** hand-painted-style material tint over the existing artist's atlas, without flattening UVs or replacing the actual sculpted rig, after manual screen review revealed a loss of faction readability when imported stock brown/green/silver assets were first substituted.

- [Chrome Actions run #42838208953](https://github.com/lordfireballzmc/BrowserGame/actions/runs/42838208953) passed **187 Vitest / 23 files**, TS, build and all original Chrome map/cinematic/pad/collision + new portrait/landscape real rigged actor probes. Map/cinematic instantiate 13 rigged actors; P01 unlocked click and P09 denial remain correct.
- **Important visual regression found before acceptance:** source Knight renders as silver/gray and raiders brown/green, so the original Bastionfall blue/gold-vs-red faction language is weaker. This required faction tinting on source PBR materials before any final merge. The revised rendering must be independently reviewed.
- **Key remaining quality gap:** even with artist-authored 3D meshes and real bone clips, the landscape still has flat green grass, generic trees/rocks, large blank gray pads, crude keep roof and a diagnostic HUD. Camera/ground contact/weapon attachment still need art-direction treatment. Native Android/iOS graphics and steady 30/60 FPS are **not measured** by Chrome/SwiftShader screenshots. One model with numerous skinned mesh subparts can increase draw calls substantially; future ART.03b must reduce skeletal mesh batches, test actual mobile GPU timing, and replace these CC0 baseline character aesthetics with a cohesive custom Bastionfall art family. Do not equate this technical achievement with full commercial visual parity.
